Loogootee Methodist Youth Jepordy

Your game. Your GitHub website.

Play on GitHub Pages without a ChatGPT login. Add a phone host using your own Firebase project.

Works with Firebase’s free Spark plan

1. Publish the game on GitHub

  1. Extract the downloaded ZIP and upload its files into the top level of your GitHub repository. You should see index.html alongside app.js and styles.css.
  2. Open Settings → Pages. Choose Deploy from a branch → main → /(root), then save.
  3. Open the website address GitHub shows. Name your teams, load your questions, and play.

Single-screen play works immediately. You can skip Firebase when you use a printed answer sheet and control the game from the computer.

2. Set up the phone connection once

Create your Firebase project

Open the Firebase console, create a project on the Spark plan, and register a Web app with the </> icon. Keep its public web configuration handy. Firebase Hosting is not needed.

Create the game host login

  1. In Authentication, enable the Email/Password provider.
  2. Under Users → Add user, create a dedicated host email and password. Copy that user’s UID.
  3. Add your GitHub Pages hostname, such as YOUR-USERNAME.github.io, to Authentication → Settings → Authorized domains.

Use the same host login on your computer and phone. Keep the password private; it does not go into GitHub or any setup file.

Protect the database

  1. Create a Cloud Firestore database in Standard edition / Native mode, using Production mode.
  2. Open the supplied firestore.rules. Replace REPLACE_WITH_HOST_USER_UID with your host UID.
  3. Copy the entire edited rules file into the database’s Rules tab and Publish. Keep access restricted by these rules.

Connect the GitHub website

Edit firebase-config.js in your GitHub repository. Set enabled to true, enter the same host UID, and replace the four web configuration placeholders.

// Public Firebase WEB configuration only. Never put a password, admin key,
// service-account JSON, or GitHub token in this file.
window.LMC_FIREBASE_CONFIG = {
  enabled: false,
  hostUid: 'REPLACE_WITH_HOST_USER_UID',
  firebase: {
    apiKey: 'REPLACE_WITH_WEB_API_KEY',
    authDomain: 'YOUR_PROJECT.firebaseapp.com',
    projectId: 'YOUR_PROJECT',
    appId: 'REPLACE_WITH_WEB_APP_ID'
  }
};

Save the change and refresh the GitHub website after it updates.

Only the public Firebase web configuration belongs here. The UID is public too. Firebase security rules and the host login control access.

3. Connect the phone and TV

  1. On the computer connected to your TV, open your GitHub website. Choose Connect phone and sign in as the game host.
  2. Choose Start TV session & get code. The computer signs out and becomes a read-only TV display.
  3. On your phone, open the same GitHub website, choose Connect phone, and sign in with the same game host login.
  4. Enter the code and choose Connect as host. Select questions, judge responses, and enter wagers on your phone. Its private answer stays off the TV until revealed.
  5. Tap Next category after reviewing the correct answer. Use End live session when finished.

Pairing codes work once and expire in 10 minutes. Sessions expire in 8 hours. Both devices need internet; they can use different networks.

The free Firebase plan

Choose Spark. This game uses host email/password sign-in and Cloud Firestore; it does not need Cloud Functions, SMS sign-in, App Hosting, or Cloud Storage.

A two-hour game with one TV display uses roughly 7,200 TV reads plus host and security-rule checks. The countdown runs locally, so it doesn’t write every second. Normal youth use should fit the allowance.

Keep the project on Spark without linking a billing account to avoid pay-as-you-go charges. If a free quota is exhausted, syncing may stop until the quota resets. Single-screen play remains available.
